# Intro و مدیریت WEB 2

## اجرا و ساخت Super Admin

فروشگاه فعال از HTML/CSS/JS ریشه، Express و SQLite داخلی Node 24 استفاده می‌کند. برنامه‌های قدیمی داخل `backend/` و پوشه‌های React تغییر نکردند.

```powershell
npm ci
Copy-Item .env.example .env
# در .env نام کاربری و رمز انتخابی خودتان را وارد کنید.
# ADMIN_PASSWORD حداقل ۱۲ کاراکتر و حداکثر ۷۲ بایت UTF-8
npm run check
npm test
npm start
```

اگر `.env` دارید، آن را جایگزین نکنید؛ فقط گزینه‌های جدید را اضافه کنید. Backend و Frontend هر دو از `http://localhost:5000` هستند. ورود مدیریت از `http://localhost:5000/admin-login` انجام می‌شود و داشبورد `/admin` فقط پس از بررسی نشست و نقش در سرور ارسال می‌شود. مسیر `/admin.html` عمداً در دسترس نیست. برای توسعه `npm run dev` اجرا شود. Live Server و بازکردن مستقیم فایل HTML مسیر API این برنامه را فراهم نمی‌کنند.

اولین اجرای سرور با `ADMIN_USERNAME` و `ADMIN_PASSWORD`، یک حساب `bootstrap-admin` با نقش `SUPER_ADMIN` و هش bcrypt در SQLite می‌سازد. رمز پیش‌فرض یا Credential عملیاتی تولید نشده است. حساب‌های بعدی از بخش «مدیران و دسترسی‌ها» با رمز اولیه‌ای که خود مدیر ارشد وارد می‌کند ساخته می‌شوند. تغییر رمز محیطی bootstrap در راه‌اندازی بعدی هش را عوض و نشست‌های قبلی او را باطل می‌کند؛ حساب غیرفعال یا نقش تنزل‌یافته خودکار ارتقا داده نمی‌شود. آخرین مدیر ارشد فعال قابل غیرفعال‌سازی یا تنزل نیست. نشست‌های مدیریتی مشترک قدیمی پس از مهاجرت باطل می‌شوند و ورود مجدد لازم است.

## Intro و Home

Intro شامل پس‌زمینه تیره، لوگوی WEB 2، Glow، شبکه دیجیتال، نور شعاعی RGB، Fade/Scale، متن خوش‌آمد و خط پیشرفت است. از CSS و JavaScript استاندارد استفاده می‌کند؛ کتابخانه انیمیشن اضافه نشده است. مدت ۲٫۵ ثانیه، دکمه «رد کردن» و Escape پشتیبانی می‌شوند. `sessionStorage` فقط نشانِ دیده‌شدن Intro را نگه می‌دارد. احراز هویت از آن خوانده نمی‌شود.

محتوای پشت Intro موقتاً inert می‌شود و پس از بستن قابل استفاده است. `prefers-reduced-motion` Intro و حرکات غیرضروری را حذف می‌کند. Reveal بخش‌ها با IntersectionObserver و تأخیر کوتاه، Fade/Scale کارت‌ها، ورود Hero و شمارش نرم تعداد واقعی محصولات اجرا می‌شود. پیام نام کاربر پس از پاسخ موفق نشست معتبر backend ظاهر می‌شود. شمارنده‌های ۲۴/۷ و درصدهای متنی فروشگاه به آمار ساختگی تبدیل نشده‌اند.

## امکانات پنل

Sidebar جمع‌شونده و منوی افقی موبایل؛ آمار واقعی و Quick Actions؛ سه نمودار ۳۰روزه فروش/سفارش/رشد کاربران و فهرست محصولات پرفروش با جدول دسترس‌پذیر؛ ویرایش محصول، قیمت، موجودی، تصویر، ویژگی، دسته‌بندی، تخفیف و نشان‌های ویژه/جدید/پرفروش؛ جست‌وجوی محصول و فیلتر کم‌موجود؛ عملیات گروهی فعال/غیرفعال/حذف/دسته‌بندی؛ جزئیات و فاکتور سفارش؛ جست‌وجو و فیلتر وضعیت؛ مدیریت حساب مشتری؛ کد تخفیف؛ تیکت و پاسخ؛ مدیران، مجوزها و Audit Log؛ تنظیمات سایت؛ جست‌وجوی عمومی بین منابع مجاز.

تنظیمات شامل نام، لوگو، توضیحات، تماس، شبکه‌های اجتماعی، بنر، اعلان زمان‌دار، هزینه ارسال، حد ارسال رایگان، محصولات ویژه، توقف ثبت سفارش و سه preset امن رنگ است. لینک‌ها فقط HTTPS یا مسیر داخلی معتبر می‌پذیرند. اعلان و بنر از داده واقعی سرور ساخته می‌شوند؛ هیچ سفارش، کاربر، تیکت یا درآمد ساختگی ایجاد نشده است. درآمد فقط سفارش‌های `paymentStatus=paid` تأییدشده را شامل می‌شود؛ سفارش آزمایشی درآمد محسوب نمی‌شود. هفته از شنبه و منطقه زمانی پیش‌فرض تهران است.

حذف محصول، حذف کد، غیرفعال‌کردن مدیر، تغییر نقش و لغو سفارش Confirmation Modal دارند. فرم‌ها هنگام ارسال قفل می‌شوند، بارگیری مشترک داشبورد درخواست تکراری ایجاد نمی‌کند و خطاها پیام فارسی دارند. حفظ قابلیت‌های موجود فاکتور، تیکت، اعلان و حساب مشتری با تست‌های قبلی بررسی شده است.

## نقش‌ها

| نقش | مجوز |
| --- | --- |
| SUPER_ADMIN | تمام عملیات مدیریتی، مدیریت مدیران و تنظیمات سایت |
| ADMIN | محصول، سفارش، مشتری، تخفیف، پشتیبانی، تحلیل، محتوا و مشاهده Audit؛ بدون مدیریت مدیران و تنظیمات |
| ORDER_MANAGER | داشبورد محدود و مشاهده/تغییر سفارش |
| PRODUCT_MANAGER | داشبورد محدود و محصولات/موجودی |
| SUPPORT | داشبورد محدود، اطلاعات عمومی محدود مشتری و تیکت؛ بدون سفارش و محصولات |
| USER | فقط حساب مشتری و منابع متعلق به همان حساب |

هر درخواست در سرور نقش و مجوز را بررسی می‌کند؛ دکمه‌های مخفی تنها UX هستند. نقش legacy `admin` در رکورد مشتری، نشست مدیریت ایجاد نمی‌کند. حساب مدیر مستقل از حساب مشتری است. تغییر نقش یا غیرفعال‌سازی مدیر نشست‌هایش را حذف می‌کند. اطلاعات رمز، هش، Token و Secret در خروجی مدیریت و Audit وجود ندارند.

## APIهای جدید

| مسیر | روش |
| --- | --- |
| `/api/site-settings` | GET عمومی |
| `/api/admin/analytics?days=7\|30\|90` | GET |
| `/api/admin/admins` | GET / POST |
| `/api/admin/admins/:id` | PUT |
| `/api/admin/permissions` | GET |
| `/api/admin/audit?q=&offset=` | GET، ۱۰۰ رکورد در هر صفحه |
| `/api/admin/settings` | GET / PUT |
| `/api/admin/search?q=` | GET، نتیجه محدود و مطابق مجوز |
| `/api/admin/products/bulk` | POST |
| `/api/admin/discounts/:id` | DELETE، نیازمند `confirm:true` |
| `/api/admin/users/:id` | GET، اطلاعات عمومی |
| `/api/admin/users/:id/orders` | GET، نیازمند مجوز سفارش |

مسیرهای موجود login/session/logout مدیریت، محصولات، سفارش‌ها، کاربران، تخفیف‌ها، تیکت‌ها و اعلان‌ها اکنون RBAC دارند. Login اطلاعات عمومی مدیر و فهرست مجوزها را برمی‌گرداند. تخفیف دارای `startsAt` و `minPurchase` شد. Quote و Order هزینه ارسال و مبلغ نهایی را در سرور محاسبه می‌کنند. Maintenance فقط ثبت/Quote سفارش جدید را متوقف می‌کند و دسترسی ورود/حساب/مدیریت برای بازیابی تنظیمات باقی می‌ماند. تغییر پرداخت تأییدنشده به Paid و لغو پرداخت واقعی بدون refund معتبر همچنان ممنوع‌اند.

## Database و امنیت

مهاجرت افزایشی با `CREATE TABLE IF NOT EXISTS` انجام می‌شود:

- `admin_accounts`: شناسه، نام کاربری یکتا، هش bcrypt، نقش معتبر، فعال‌بودن، الزام TOTP و تاریخ‌ها.
- `audit_logs`: شناسه ترتیبی، مدیر، نقش، عملیات، نوع/شناسه هدف، جزئیات امن و زمان؛ ایندکس زمان.
- `settings` موجود: رکورد JSON جدید `site-config`.
- JSON محصول: `featured`, `isNew`, `bestSeller`؛ تخفیف: `startsAt`, `minPurchase`؛ سفارش: `shippingCost`.

SQLite پیش‌فرض `var/web2.sqlite` است. داده قبلی حفظ شده است. برای Production، HTTPS و `APP_ORIGIN` دقیق و `NODE_ENV=production` لازم‌اند. کوکی HttpOnly، SameSite Strict، Secure در Production، CSRF حتی روی alias قدیمی محصول، کنترل Origin، اعتبارسنجی ورودی و محدودیت درخواست برقرار است. پس از ۵ تلاش ناموفق ورود مدیر، IP/نام کاربری ۱۵ دقیقه محدود می‌شود. این محدودکننده در حافظه یک پردازه است؛ استقرار چندپردازه نیازمند storage مشترک limiter است.

2FA اختیاری برای حساب bootstrap: **Secret خودتان** را از سیستم provisioning معتبر به‌صورت Base32 در `ADMIN_TOTP_SECRET` سرور قرار دهید و در authenticator خود ثبت کنید. کد ۶رقمی TOTP در Login لازم می‌شود. حذف Secret بعد از فعال‌سازی موجب fail-closed می‌شود. Secret نه تولید شد، نه در Frontend/Database نمایش داده می‌شود. ثبت‌نام TOTP جداگانه و Recovery Code برای هر مدیر در این نسخه ایجاد نشده است.

## تست و محدودیت اجرا

`tests/admin.test.cjs`: API واقعی روی SQLite موقت، چهار نقش محدود، منع ارتقای خود، هش رمز، حفظ آخرین Super Admin، تغییر و ابطال نشست، محصول/موجودی/Bulk، تخفیف/ارسال، Maintenance، CSRF alias، سفارش و منع Paid جعلی، جست‌وجوی محدود، Audit، UI واقعی DOM با API برای نمودار/مدیران/تنظیمات/ویرایش محصول، Intro و Skip/Refresh/reduced-motion/پیام حساب، TOTP و Brute Force.

تست‌های حساب موجود شامل Register → Login → Dashboard → Profile → Address → Wishlist → Cart → Orders → Detail → Ticket → Logout → Login مجدد و منع دسترسی User A به User B هستند. `npm run check` syntax، لینک‌ها، شناسه‌ها و CSP را بررسی می‌کند.

مرورگر قابل کنترل در این محیط در دسترس نبود؛ تست DOM با jsdom انجام شد و بررسی بصری واقعی موبایل/تبلت و اجرای GPU انیمیشن ادعا نمی‌شود. پیش از انتشار، این بررسی بصری را روی staging انجام دهید. پرداخت واقعی و refund همچنان نیازمند Provider رسمی هستند. تصاویر/موجودی/داده فعلی کاتالوگ نمایشی‌اند و باید توسط فروشگاه تنظیم شوند. پیامک، ایمیل، بازیابی رمز و TOTP enrollment کامل هر مدیر نیازمند اتصال/توسعه جداگانه‌اند.
